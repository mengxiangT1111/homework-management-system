> 基于 2026-09-30 对 Web 前端、后端、微信小程序、Python 查重服务、部署脚本的全量代码扫描，并与《AI批改与查重升级方案.md》（A/P/L 条目）对齐。
> 结论先行：**系统核心链路已完整闭环，不存在烂尾模块**；需要补的东西集中在四类——上线人工操作、后端已建好但无界面的能力、方案文档已规划但未动工的算法升级、工程质量与体验短板。

## 一、现有功能全景

### 架构总览（三端一服务）

| 端 | 技术 | 规模 | 完成度 |
|---|---|---|---|
| Web 前端 | Vue3 + Element Plus + ECharts + Pinia | 学生 10 页 / 教师 11 页 / 管理员 9 页 | 高，无空页面无假数据 |
| 微信小程序 | uni-app + Vue3 | 15 页（学生+教师双角色） | P0 功能完整，唯一发布阻断是 AppID 占位 |
| 后端 | Express + Sequelize + MySQL8 | 14 组路由、30+ 数据模型、批改+查重双队列 worker | 高 |
| 查重微服务 | Python FastAPI + PaddleOCR + OpenCV + networkx | 四级渐进检测流水线 | 高，但未纳入 compose 编排 |

### 核心链路（已闭环）

1. **作业域**：教师/班长/学委/课代表三级代发 → 学生分片上传（秒传/断点续传/防冒绑）→ 逾期拦截 → 打包下载/未交 Excel/催交
2. **AI 批改域**：教师 rubric 模板（维度+权重+档位+扣分规则）→ 批量任务（MySQL 队列、防重复建单、指数退避、熔断、僵死回收）→ 提示词版本库 + 确定性灰度路由 → 注入防御（数据围栏+零宽转义）→ 三重兜底解析 + 服务端算总分 → 置信度分流（高置信自动回写 / 低置信转人工复核 / 满分强制复核）→ 复核闭环（通过/调整/否决）
3. **查重域**：全班 C(n,2) 异步任务 → 四维检测（pHash 初筛 / ORB 特征 / OCR 文本 Jaccard / 图结构同构+近似 GED）→ 双向成对入库 → 可疑分级 + 双拓扑 Canvas 对比可视化
4. **支撑域**：三角色权限（JWT + 密码版本指纹）、班委/课代表职务、待办系统、站内通知（cron 截止提醒）、操作审计日志（180 天保留）、文件清理、LibreOffice 在线预览、COS 可选存储、ECharts 统计
5. **学情分析域**（2026-10-01 新增）：基于提交行为/成绩/查重三源数据的学生学情画像（提交率、逾期、归一化均分、成绩趋势、查重最高相似度）+ 三级风险判定（高/中/低，附可解释原因）→ 教师端「学情分析」页（课程 KPI、班级成绩趋势图、学生画像表、共性错误归纳、查重风险监控、未交一键催办、风险学生预警通知）；学生端仪表盘「我的学情」自查卡片。全部由既有表聚合计算，无新增数据表

## 三、现有功能升级项（功能已有、实现待升级）

> 与第二节"缺口清单"的区别：本节列的是**已经存在、能正常工作、但实现版本明显落后**的功能，属于原地升级而非补缺。按升级收益分三档。

### 3.1 内核算法级（决定论文与答辩成色）

| 现有功能 | 现在的实现 | 升级方向 |
|---|---|---|
| 置信度分流 | 5 条手工规则加法扣分（起点 1.0 逐项扣减），不是模型真实置信度；0 分异常仅 -0.10 仍可能自动回写 | 用金标数据标定为校准分数，叠加自一致性双评（A2：同题批两次、分差大才转复核）——与第 1 期 A3 是同一件事，双评是其增强形态 |
| 查重文本相似度 | 整图 OCR 词集合 Jaccard（无序、无局部对齐）；docx 为字符 Jaccard + 截断 500 字编辑距离——检不出局部抄袭与同义改写 | Winnowing 指纹/局部对齐 + 语义 embedding 通道（P3 的文本/语义部分，建议从第 3 期提前） |
| 查重权重与阈值 | 图 0.5/文本 0.2、可疑线 50/75 硬编码在 Python 源码 | 配置化 + 教师 verdict（确认/误报）回流校准（P4，已列第 2 期） |
| 批改文本提取 | 仅 txt/docx，超 3 万字直接截断 | PDF/手写 OCR 接入（A1，已列第 1 期）+ 长作答分题切分（A7） |

### 3.2 功能能力级（决定真实可用性）

- **单份 AI 批改 / 单人查重**：同步阻塞 300~600 秒、无进度不可取消 → 入队异步（队列基建现成，等于把旧入口搬上新轨道；对应 E3，随第 2 期第 6 项落地）
- **通知系统**：纯站内信 + 60 秒轮询 → 微信订阅消息 + 邮件（第 2 期第 2 项）。小程序用户不打开 App 就收不到任何提醒，这条对真实使用影响最大
- **账号体系**：手机号/邮箱存了但零使用，忘记密码只能找管理员 → 验证码自助找回（随第 2 期通知升级一起做，对应 D5）
- **小程序上传**：多文件串行、单个失败中止整批、仅压缩图 → 并行 + 失败续传 + 原图选项（E7，第 2 期第 8 项）
- **管理员统计**：目前仅 1 张提交率柱状图 → **批改质量看板**：置信度分布、复核率、AI 分 vs 教师复核分偏差分布、查重可疑率趋势——把置信度分流的运行效果可视化，结题演示说服力最强（新增项，未列入分期，按精力插入第 1-2 期）
- **复核工作台**：目前只有队列 + 通过/调整/否决 → 指派 + 查重徽标同屏 + AI 依据在学生原文上高亮（B3 第 2 期 + L1 第 1 期 + A6 第 3 期，可打包推进）
- **成绩模型**：score DECIMAL(5,2) 靠 999.9 钳制支撑千分制模板 → DECIMAL(6,2) 迁移（D2，第 2 期第 3 项）

### 3.3 体验级（决定口碑，小活）

批量批改把 needs_review 计进"失败 N 人"的口径（E4）、已发布模板仍开放保存（E5）、课代表编辑样例缺视频 tab（E6，顺手并入第 2 期第 6 项）、学生列表无 loading（E1）、system 类消息点击不跳转、Python 可视化端点空壳（E9，第 2 期第 9 项）。

### 3.4 若只挑三个

1. **置信度校准 + 双评**：与论文 D 消融共用数据，一鱼两吃（第 1 期第 1 项）；
2. **查重文本算法换 Winnowing/embedding**：补上检不出局部抄袭/同义改写的最大短板，建议从第 3 期提前；
3. **订阅消息通知**：真实可用性的质变（第 2 期第 2 项，可视需要提前）。

批改质量看板属演示加分项，时间充裕即做。
