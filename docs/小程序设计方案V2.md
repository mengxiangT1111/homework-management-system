# 微信小程序端设计方案 V2

> V1 复审后修订。V1 文档保留于同目录作对照。文末附 V1 → V2 变更摘要。

---

## 1. 定位与范围（不变）

小程序 = 学生/教师的移动高频入口；管理端、查重中心、AI 模板管理、zip/Excel 导出留在 Web。

**P0 范围（13 页）**：
- 公共：登录、消息中心、我的、改密码
- 学生：首页、作业列表、作业详情、提交作业、提交记录、成绩与 AI 结果查看、我的班级
- 教师：工作台（即首页）、作业列表（课程/状态筛选）、作业详情（提交进度/未交名单/催交/AI 批改任务）、创建/编辑作业（含关闭/重开）、批改页（预览/打分/评语/AI 结果）、**AI 复核队列（V2 新增）**

**明确不进小程序**：管理员全部功能、查重可视化、模板/提示词编辑器、zip 打包、Excel 导出、分片上传、课代表/助教收集流（低频，Web 使用）。

## 2. 总体架构（不变，接口契约全部核实过）

```
┌─────────────┐     ┌──────────────────┐
│ 微信小程序   │     │  Web 前端 (Vue3)  │
│ uni-app     │     │  （保持不动）      │
└──────┬──────┘     └────────┬─────────┘
       │  HTTPS + JWT        │
       ▼                     ▼
┌──────────────────────────────────────┐
│  现有 Express 后端（唯一新增：        │
│  POST /api/upload/single）           │
│  其余 /api/* 全部复用                │
└──────┬───────────────┬───────────────┘
       ▼               ▼
   MySQL 8        腾讯云 COS（签名 URL 访问）
```

文件访问统一走 `POST /api/files/urls`（body `{paths: [...]}`，返回 `{文件路径: 访问URL}`）：
- COS 文件返回**签名 URL**（1 小时时效，兼容私有/公共桶）
- 本地文件返回**相对路径** `/api/files/download?path=...&token=...`，小程序端必须拼上 BASE_URL

## 4. 关键技术方案（V2 修订点加粗）

### 4.1 登录与鉴权
- 复用 `POST /api/auth/login`（`username + password + school_id`）；`GET /api/schools/all` 免登录拉学校下拉
- **登录接口有 IP 限流（15 分钟 10 次）**，连续失败提示透出服务端 message（"账号已被临时锁定"）
- admin 角色拒绝进入小程序（提示用网页端）
- token 校验：App 启动 `GET /api/auth/profile`，401 清态

### 4.2 文件上传
- 新增 `POST /api/upload/single`：multer 单文件、字段名 `file`、上限 100MB、扩展名黑名单与 `fixMojibakeName` 中文文件名处理与现有一致；落盘/COS 双模式与 `mergeChunks` 相同；返回 descriptor `{original_name, file_path, file_size, mime_type, file_hash, ext}`（hash 为 null）
- 小程序端逐个**串行** `uni.uploadFile`，**必须设置 timeout（默认 60s，大文件必超时）**，带 onProgressUpdate 进度；失败单文件重试
- 前置校验：allowed_formats / max_files / max_size_mb；超 100MB 引导网页端
- 重复提交：已提交的作业可再次提交**覆盖**（后端 upsert），按钮文案"重新提交（将覆盖）"+ 二次确认

### 4.3 文件预览
- 统一 `POST /api/files/urls` 取签名 URL（**即时获取、不缓存**——签名 1 小时过期）；本地文件返回的相对路径拼 BASE_URL
- `uni.downloadFile` → 按扩展名分流：图片 `uni.previewImage`；pdf/doc/docx/xls/xlsx/ppt/pptx `uni.openDocument`（**显式传 fileType 映射**）；zip 等提示网页端查看
- `is_cleaned=1` 的文件显示"文件已过期清理"，不出现预览按钮
- COS 域名 + API 域名均加入小程序后台 downloadFile 合法域名

### 4.4 作业列表的"免费"状态字段（后端已聚合，前端零额外请求）
`GET /api/assignments` 每行已附加：
- `is_overdue`（是否逾期）
- 学生视角：`my_submission`（我的提交对象或 null）
- 教师视角：`submit_count`（已交人数）
- 含 `course`（含 class 班级名）、`teacher.real_name`

学生"待交作业" = `status=active && !my_submission`，直接客户端过滤，无需逐个查询。

### 4.5 AI 批改链路（教师）
- **批量批改**：`POST /api/grading/tasks/batch` 必传 `assignment_id + template_id`（模板列表 `GET /api/grading/templates?status=published`），可选 `mode`（balanced/strict/encouraging）、`reference_answer`、`force`
- 进度轮询 `GET /api/grading/tasks?assignment_id=`（3s 间隔，运行中显示进度条，pending 可取消）
- **复核队列（V2 新增为 P0 页面）**：低置信度 AI 结果会挂起待复核，教师不处理则学生长期无分。`GET /api/grading/reviews?status=pending` → 三个动作 `POST /api/grading/reviews/:id`，body `{action: approve|adjust|reject, final_score?, comment?}`
- AI 结果渲染字段（学生/教师共用）：`total_score / full_score / confidence / needs_review / overall_feedback / improvement_advice / dimension_scores[{code,name,max_score,score,feedback}]`

### 4.6 手动打分
- `PUT /api/submissions/:id/grade`，body `{score, comment}`；服务端校验 0–100（该提交已有 AI 结果且模板满分 >100 时上限随之放宽），前端只做 0–100 预检，越界错误透出服务端 message
- 打分成功自动 status=graded 并通知学生（服务端处理）

### 4.7 通知与角标
- Tab 页 `onShow` 拉 `GET /api/notifications/unread/count` → `uni.setTabBarBadge({index: 2})`
- 通知点击：`type=deadline/assignment` → `related_id` 为作业 ID，跳作业详情（页面按角色自适应）；`type=grade` → 学生跳作业详情看成绩；`type=system` 仅标记已读

### 4.8 作业管理补充（V2 新增）
- 教师可在作业详情**关闭/重开**作业：`PUT /api/assignments/:id {status}`，关闭后学生端提交入口消失
- **编辑作业**：复用创建表单（预填），`PUT /api/assignments/:id`；截止时间须晚于当前时间（服务端校验）

## 6. 风险与对策（V2 增补加粗）

| 风险 | 对策 |
|---|---|
| **隐私 API 强制合规**：未在 mp 后台配置《用户隐私保护指引》时，`chooseMedia`/`chooseMessageFile` 等隐私接口直接调用失败（2023-09 起强制） | 提审前在后台"设置→服务内容声明"配置隐私指引（相册、摄像头、选中的文件、学号姓名）；开发工具与真机分别验证选文件可用 |
| 小程序类目/资质审核 | 按"工具-效率"或主体资质匹配类目申请；不强制微信授权登录降低审核门槛 |
| 大文件上传超时 | uploadFile 显式 timeout 300s；>100MB 拦截引导网页端；失败单文件重试 |
| **签名 URL 过期导致预览失败** | 预览时即时调 `/api/files/urls`，不持久化 URL；失败自动重新取一次 |
| iOS Date 解析 NaN | 统一时间工具（`-`→`/` 后解析）；倒计时/逾期展示集中处理 |
| **uni-ui easycom 未配置导致组件空白** | V2 提示词内嵌确切配置片段 |
| 包体积 | 13 页全主包 < 1.5MB；后续按需分包 |
| 登录限流误伤（校园网出口 IP 共享） | 失败提示透出服务端 message；如遇普遍误锁，服务端调 limiter 参数（Web 端同享此限流，非小程序新增风险） |

## 7. 里程碑（V2 更新）

1. **M1 骨架**：uni-app 工程（easycom/Pinia/请求层/常量）+ 后端 `/api/upload/single` + 登录页
2. **M2 学生链路**：首页 → 列表 → 详情 → 提交（串行上传/重提交）→ 记录 → 成绩与 AI 结果
3. **M3 教师链路**：工作台 → 列表/筛选 → 创建/编辑/关闭作业 → 详情（提交/未交/催交/AI 任务发起与进度）→ 批改页 → **复核队列**
4. **M4 收尾**：消息 + 我的 + 班级；真机自测（含隐私 API 验证）+ 验收清单 + 提审材料

## V1 → V2 变更摘要

**契约修正（V1 不精确会让 AI 踩坑）：**
1. `POST /api/files/urls` 精确契约为 body `{paths:[]}`、返回映射表；**本地文件返回相对路径必须拼 BASE_URL**——V1 未写清，这是最容易翻车的点
2. 文件预览从"公共读桶直出"修正为"统一签名 URL（即时获取不缓存）"，兼容私有/公共桶
3. 补齐作业列表已内置的聚合字段（`my_submission`/`submit_count`/`is_overdue`），学生待交作业无需额外请求
4. 补齐打分上限规则、提交详情 data 可能为 null、`uploadFile` 需显式 timeout 等细节
5. AI 结果渲染字段明确（dimension_scores 等），复核队列给出完整请求/响应契约

**范围调整：**
6. 新增 P0 页面：教师 **AI 复核队列**——V1 只有假入口没有页面（违反自身"无假入口"原则），且教师不处理复核学生就一直没分
7. 新增：教师**关闭/重开作业**、**编辑作业**（复用表单，高价值低成本）
8. 明确**重新提交（覆盖）**流程：确认弹窗 + 文案提示
9. 明确通知点击跳转规则；批量 AI 批改必须选模板（V1 漏了 template_id 依赖）

**工程防坑：**
10. 新增"陷阱清单"专节（12 条），内嵌 easycom/Pinia 确切配置片段，防 AI 高频翻车

**合规：**
11. 新增隐私 API 强制合规风险与对策（未配置隐私指引时选文件接口直接失败）
