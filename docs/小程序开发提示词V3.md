## 1. 系统硬约定（已核实，必须严格遵守）

1. **API 前缀 `/api`**，响应统一 `{ code, success, message, data }`。`success === false` 时把 `message` 原样 toast 给用户。
2. **鉴权**：`Authorization: Bearer <token>`。任何 401 → 清本地登录态 + `uni.reLaunch` 登录页，并发 401 去重（只跳一次）。
3. **分页**：`?page=1&pageSize=10` → `data: { list, total, page, pageSize, totalPages }`。
4. **登录**：`POST /api/auth/login`，body `{ username, password, school_id }`（师生必选学校）。返回 `{ token, user }`（sanitizeUser：除 password 外全字段，含 school_id）。登录接口有 IP 限流（15 分钟 10 次），失败提示透出服务端 message。`user.role === 'admin'` → 提示"请使用网页端登录"，不进入系统。
5. **文件访问**（最容易做错的点）：
   - 统一 `POST /api/files/urls`，Header 带 token，body `{ "paths": ["uploads/202607/xx.pdf", "cos://homeworks/202607/yy.docx"] }`（≤100 项）
   - 返回 `data` 为映射表 `{ "<path>": "<url 或 null>" }`
   - **COS 文件返回签名 URL（1 小时时效）：即用即取，禁止缓存/落库**
   - **本地文件返回相对路径 `/api/files/download?path=...&token=...`：交给 `uni.downloadFile` 前必须拼 `BASE_URL`**
   - 作业样例文件结构为 `[{name, type, url}]`，其中 `url` 就是 file_path，直接作为 paths 传入
6. **提交契约**：`POST /api/submissions/assignment/:id`，body `{ files: [{ original_name, file_path, file_size, mime_type, file_hash }], remark }`。重复调用=覆盖更新。逾期/关闭/超量/格式由后端校验，前端做预检 + 透出错误。
7. **列表接口已内置聚合字段，禁止为同样的信息再发请求**：
   - `GET /api/assignments` 每行：`is_overdue`；学生视角 `my_submission`（Submission 对象或 null，含 status/score）；教师视角 `submit_count`；含 `course`（含 `class.name`）与 `teacher.real_name`
   - `GET /api/assignments/:id`（学生）：已内嵌 `my_submission`（含 files 数组）——**学生详情页唯一数据源**
   - `GET /api/assignments/:id/submissions`（教师）：一次返回 `{ assignment:{id,title,deadline,is_overdue,allowed_formats,max_files,course_name,class_name}, students:[{student_id, username, real_name, submitted, submission}], total_students, submitted_count, unsubmitted_count }`——**教师详情页唯一数据源**（进度 + 全员名单 + 提交对象都在这；`submission` 含 id/score/status/files）
8. **时间**：解析一律 `utils/format.js#parseDate`（`-`→`/` 再 `new Date`，规避 iOS NaN）。deadline 展示与倒计时仅做展示，判定以后端为准。
9. **打分**：`PUT /api/submissions/:id/grade`，body `{ score, comment }`；服务端校验 0–100（该提交有 AI 结果且模板满分>100 时上限放宽），前端预检 0–100，越界透出服务端 message。
10. **改密码**：`PUT /api/auth/password`，body `{ old_password, new_password }`。**服务端不会使旧 JWT 失效**——成功后前端清本地登录态跳登录页即可，不要在 UI 上宣传"已使旧登录失效"。

## 3. 后端唯一新增接口：`POST /api/upload/single`

在 `server/src/controllers/uploadController.js` + `server/src/routes/upload.js` 新增（`router.use(auth)` 已覆盖，风格与现有一致）：

- **不改动**现有 check/chunk/merge/simple 接口的任何行为

## 6. 关键实现方案

### 6.1 请求层 `utils/request.js`
Promise 化 uni.request；自动注入 token；`success === false` → toast(message)+reject；401 → 清 storage + reLaunch 登录页（并发去重）；网络异常统一文案。导出 get/post/put/del；`uploadFile(url, filePath, filename)` 独立封装（带 token、timeout 300s、JSON.parse、success 判定）。

### 6.2 环境配置 `utils/config.js`
`BASE_URL`：开发 `http://<本机局域网IP>:3000`（真机同局域网），生产 `https://你的域名`，注释切换方式。

### 6.3 文件预览 `utils/preview.js`
`POST /api/files/urls` 即时取 URL（本地路径结果拼 BASE_URL）→ `uni.downloadFile` → 图片走 `uni.previewImage`；pdf/doc/docx/xls/xlsx/ppt/pptx 走 `uni.openDocument` **显式传 fileType**；zip/其他 → "该格式请在网页端查看"。预览失败自动重取 URL 再试一次。

### 6.4 消息角标
tab 页 onShow 调 unreadCount → >0 时 `uni.setTabBarBadge({index:2, text:String(n)})`，=0 时 remove。

### 6.5 通用

## 7. 陷阱清单（实现时逐条对照）

1. **easycom 未配置 → uni-ui 组件全部静默不渲染**
2. **本地文件预览用相对路径 → downloadFile 报 url invalid**（拼 BASE_URL）
3. **签名 URL 缓存复用 → 1 小时后 403**（即用即取）
4. **uploadFile 不设 timeout → 大文件 60s 必超时**（显式 300s）
5. **`uni.uploadFile` 的 `res.data` 是字符串**（JSON.parse + 判 success）
6. **iOS `new Date('2026-08-30 23:59')` 为 Invalid Date**（统一 parseDate）
7. **未提交时 `my_submission`/detail 接口 data 为 null**（判空）
8. **批量批改漏传 template_id → 422**（必须先拉 published 模板）
9. **进度轮询不停止**（终态 clearInterval；onUnload 也清）
10. **tabBar 角标 index 固定为 2**（消息第 3 位）
11. **401 并发无去重 → 反复 reLaunch**（参照 Web 端 redirectingToLogin 模式）
12. **admin 登录进入业务页**（登录成功即按 role 分流拦截）
13. **编辑已逾期作业原样回传旧 deadline → 422**（只提交变更字段）
14. **system 通知的 related_id 当作业 ID 跳转 → 404**（system 一律不跳）
15. **复核队列行里找作业标题**（不存在该字段，不要逐行补查）
