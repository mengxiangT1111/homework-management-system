# 微信小程序端设计方案 V3

> V2 复审后修订（本轮将 V2 中所有"让 AI 自行阅读"的接口契约逐个在源码中核实并写死）。V1/V2 保留于同目录对照。文末附 V2 → V3 变更摘要。

---

## 1. 定位与范围（不变）

小程序 = 学生/教师的移动高频入口；管理端、查重中心、AI 模板管理、zip/Excel 导出、课代表收集流留在 Web。

**P0 范围（13 页，与 V2 相同）**：
- 公共：登录、消息中心、我的、改密码
- 学生：首页、作业列表、作业详情、提交作业、提交记录、我的班级
- 教师：工作台、作业列表（筛选）、作业详情（进度/名单/催交/AI 批改任务）、创建/编辑作业、批改页（预览/打分/AI 结果/**复核操作条**）、复核队列

**V3 新增进 P0**：学生端查看 AI 批改详情（V2 遗漏——AI 批改是本系统核心特性，学生看不到 AI 结果等于砍掉一半价值）。

## 4. 关键技术方案（V3 修订点加粗）

### 4.1 请求合并（V3：页面级"单一数据源"）
本轮核实发现多处接口已聚合返回，**以下页面各只需 1 个业务请求**，禁止 AI 拆成多次调用：
- **学生作业详情**：`GET /api/assignments/:id` 已含 `my_submission`（含文件列表）
- **教师作业详情**：`GET /api/assignments/:id/submissions` 一次返回 `{assignment, students:[{…, submitted, submission}], total_students, submitted_count, unsubmitted_count}`——进度、已交、未交全部在内
- **学生待交作业**：`GET /api/assignments` 行内已含 `my_submission`/`is_overdue`，客户端过滤

### 4.2 登录与鉴权（不变）
登录 `{username, password, school_id}`（学校下拉免登录）；IP 限流提示透出；admin 拒入；**改密码成功后前端清本地态回登录页（服务端 JWT 无失效机制，旧 token 到期前仍有效，不宣传"失效"）**。

### 4.3 文件上传（不变，细节已写死）
新增 `POST /api/upload/single`（multer 单文件 / 100MB / 黑名单 / `fixMojibakeName` / COS+本地双模式 / 返回与 merge 一致的 descriptor，hash=null）；小程序串行 `uni.uploadFile`（timeout 300s、进度、单文件重试）；`chooseMedia`/`chooseMessageFile` 的 count 用"剩余可传数"。

### 4.4 文件预览（不变）
统一 `POST /api/files/urls`（body `{paths}`，返回映射表；COS=签名 URL 即用即取，本地=相对路径拼 BASE_URL）；openDocument 显式 fileType；`is_cleaned=1` 显示"已过期清理"。

### 4.5 创建/编辑作业的精确载荷（V3 写死）
- `deadline`：**`YYYY-MM-DD HH:mm:ss` 字符串**（与 Web value-format 一致）
- `need_grading`：boolean（服务端自行转 0/1）
- `allowed_formats`：字符串数组（默认 pdf,doc,docx,jpg,png,zip）
- **编辑陷阱**：服务端仅在请求携带 `deadline` 时校验"晚于当前时间"。编辑已逾期作业时，**未修改的字段（尤其 deadline）不要回传**，否则 422
- 小程序创建作业不含样例文件上传（已知限制，样例文件在 Web 端维护；学生端只读展示）

### 4.6 AI 批改链路（V3 结构化）
- **批量批改**：先 `GET /api/grading/templates?status=published` 选模板（必传 template_id），`POST /api/grading/tasks/batch` `{assignment_id, template_id, mode?, reference_answer?, force?}`
- **进度**：`GET /api/grading/tasks?assignment_id=` → `{progress:{total,pending,processing,success,failed,cancelled}, list:[{status, student_name, error_msg, submission_id}]}`；3s 轮询至终态，onUnload 清定时器
- **复核**：队列 `GET /api/grading/reviews?status=pending`（行含 result.total_score/full_score/confidence、submission.student.real_name、original_score；**不含作业标题，勿逐行补查**）。**交互简化（V3）**：点行 → 跳批改页并带 `&reviewId=` → 批改页底部出现"复核操作条"（采纳/调分/驳回，`POST /api/grading/reviews/:id`）——复核复用批改页的文件预览与 AI 结果卡，不另做展开 UI

### 4.7 学生端 AI 结果展示（V3 新增）
学生"我的提交"卡内联展示：`score` 有值正常显示；`score` 为空但 AI 结果存在时显示"AI 已评，待教师确认"。可展开查看：总分/满分、置信度、`overall_feedback`、`improvement_advice`、`dimension_scores[{name, score, max_score, feedback}]`。接口与教师共用 `GET /api/grading/results/submission/:id`（本人可查）。

### 4.8 通知跳转（V2 规则保留 + 边界明确）
type ∈ deadline/assignment/grade 且 related_id 存在 → 跳作业详情；**type=system 的 related_id 不是作业 ID（可能是用户 ID），一律不跳转**，仅标记已读。

## 6. 风险与对策（在 V2 基础上微调）

| 风险 | 对策 |
|---|---|
| 隐私 API 强制合规（未配置隐私指引时选文件失败） | 提审前配置《用户隐私保护指引》；真机验证选文件 |
| 类目/资质审核 | "工具-效率"类目；不强制微信授权登录 |
| 大文件上传超时 | uploadFile timeout 300s；>100MB 引导网页端；单文件重试 |
| 签名 URL 过期 | 即用即取不缓存；失败自动重取 |
| iOS Date NaN | 统一 parseDate |
| easycom 未配置组件空白 | 提示词内嵌配置片段 |
| 编辑已逾期作业误传旧 deadline 被 422 | 表单只提交有变化的字段（V3 新增） |
| 包体积 / 登录限流 | 同 V2 |

## V2 → V3 变更摘要

**冗余调用消除（本轮逐个核实接口后的修正）：**
1. 学生作业详情 1 个请求搞定（`GET /api/assignments/:id` 已内嵌 `my_submission`+files），删除 V2 的额外调用
2. 教师作业详情 1 个请求搞定（`GET /api/assignments/:id/submissions` 已含 total/submitted/unsubmitted 计数与全员名单+submitted 标记），`/:id/unsubmitted` 从必用清单移除
3. 复核队列行**不含作业标题**（服务端 include 只有 student），V2 的展示要求会迫使 AI 逐行补查——已修正；复核交互简化为"队列点行 → 批改页带 reviewId 出复核操作条"，复用文件预览与 AI 结果卡

**契约精确化：**
4. 统计接口字段写死：student `{classCount, courseCount, totalAssignments, mySubmissions, graded, pendingSubmit}`；teacher `{courseCount, assignmentCount, submissionCount, gradedCount, ungradedCount}`
5. 任务进度结构写死：`{progress:{total,pending,processing,success,failed,cancelled}, list:[…]}`
6. 创建/编辑作业载荷写死：deadline=`YYYY-MM-DD HH:mm:ss`、need_grading=boolean、allowed_formats=字符串数组；**编辑只提交变更字段**（服务端仅在校验携带的 deadline）
7. 样例文件结构 `[{name,type,url}]`（url 即 file_path，直接喂 files/urls）
8. `classes/all/list` 服务端已按登录用户学校过滤，无需客户端过滤
9. 催交无需 body，服务端 1 小时去重；结果文案用返回的 reminded 计数
10. 修正 V2 验收项错误表述：改密码不会使旧 JWT 失效（服务端无失效机制），正确说法是前端清本地态回登录页

**功能补漏：**
11. **学生端查看 AI 批改详情**（V2 遗漏）：内联展开展示维度得分/评语/改进建议；"AI 已评待教师确认"状态提示
12. mine 页"我的课程"明确为页内区块而非新页面（守住 13 页）

**工程约束收紧：**
13. 明确"恰好 13 页，禁止新增页面"；交付前 `npm run build:mp-weixin` 必须通过
