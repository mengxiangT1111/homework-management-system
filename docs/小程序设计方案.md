# 微信小程序端设计方案

> 基于「在线作业提交管理系统」现有 Web 版（Vue3 + Express + MySQL）扩展微信小程序端。
> 核心思路：**复用现有后端与数据库，只新增最小接口；小程序定位为学生/教师的移动高频场景，管理功能保留在 Web。**

---

## 1. 定位与范围

小程序不是 Web 的完整复刻，而是"移动端轻量入口"，覆盖两类用户最高频的场景：

| 角色 | 高频移动场景 | 对应功能 |
|---|---|---|
| 学生 | 随时查作业、手机拍照/选文件交作业、看成绩、收提醒 | 首页、作业列表/详情、提交、提交记录、消息、我的 |
| 教师 | 随时看提交进度、手机批改打分、催交、看 AI 批改结果 | 工作台、作业管理、创建作业、批改、AI 批改任务、催交、消息、我的 |

**明确不进小程序**（留在 Web 端）：
- 管理员全部功能（用户/学校/班级/课程管理、文件清理、全局统计）
- 查重中心（复杂可视化对比图）
- AI 批改模板管理、提示词版本管理（复杂编辑器）
- 打包下载 zip、导出 Excel（小程序文件系统限制，且桌面场景更自然）
- 大文件分片上传（>100MB 引导去 Web）

---

## 2. 总体架构

```
┌─────────────┐     ┌──────────────────┐
│ 微信小程序   │     │  Web 前端 (Vue3)  │
│ uni-app     │     │  （保持不动）      │
└──────┬──────┘     └────────┬─────────┘
       │  HTTPS + JWT        │
       ▼                     ▼
┌─────────────────────────────────────┐
│   现有 Express 后端（仅新增 1 个接口）│
│   /api/upload/single ← 新增          │
│   其余 /api/* 全部复用               │
└──────┬───────────────┬──────────────┘
       ▼               ▼
   MySQL 8        腾讯云 COS（公共读桶）
```

- 同一套 JWT、同一数据库、同一文件存储（COS 优先，未配置时降级本地）
- 后端改动最小化：**必须新增的只有 `POST /api/upload/single`**（小程序单文件直传，替代 Web 的分片上传链路）

---

## 3. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **uni-app（Vue 3 + Vite，CLI 版，JS）** | 与现有 client/ 同为 Vue 3，心智一致；官方 CLI 无需 HBuilderX（`npm run dev:mp-weixin` 编译到微信开发者工具）；未来可低成本出 H5 版 |
| UI 库 | **uni-ui**（官方维护）+ 少量自定义组件 | 兼容 Vue 3 最稳，避免第三方库的编译坑 |
| 状态管理 | Pinia + `uni.setStorageSync` 持久化 | 与 Web 端 Pinia 用法一致 |
| 请求 | 自封装 `uni.request` Promise 层 | 小程序无 axios；统一处理 `{code, success, message, data}` 与 401 |
| 目录 | 仓库根新建 `miniprogram/` | 与 client、server 并列 |

> 备选：原生小程序（WXML/WXSS）零编译层、调试直接，但与现有 Vue 技术栈割裂。若团队只做微信单一端且不想有编译层，可切换，整体方案不变。

## 4. 功能分期

### P0 —— MVP（本次开发目标，约 12 个页面）

**公共**：登录（学校下拉 + 学号 + 密码）、消息中心（列表/已读/角标）、我的（资料/改密码）、4 个原生 Tab（首页/作业/消息/我的，首页与作业页按角色分支渲染）

**学生**：
- 首页：`/api/stats/student` 概览卡 + 待交作业（截止倒计时）
- 作业列表/详情：格式/数量/大小要求展示、我的提交状态
- 提交作业：`wx.chooseMessageFile`/`wx.chooseMedia` 选文件 → 逐个直传 `/api/upload/single`（带进度）→ `POST /api/submissions/assignment/:id`
- 我的提交记录、成绩与 AI 批改结果只读查看
- 我的班级（`/api/classes/my/list`、加入 `join` / 退出 `leave`）

**教师**：
- 工作台：`/api/stats/teacher` 统计 + 近期截止作业
- 课程下拉筛选作业列表、创建作业表单（标题/说明/课程/截止时间/格式/数量/大小/是否需批改）
- 作业详情：提交进度、已交名单、未交名单、催交
- 批改页：文件预览（PDF/Word/图片）→ 打分 + 评语 → `PUT /api/submissions/:id/grade`
- AI 批改：查看单份结果 `GET /api/grading/results/submission/:id`；批量任务进度轮询 `POST /api/grading/tasks/batch` + `GET /api/grading/tasks`（P0 可选）

### P1 —— 增强（二期）
- 微信一键登录绑定（`code2session` + users 表加 openid 字段，`POST /api/auth/wechat/session`）
- 订阅消息推送（截止提醒、批改完成通知，需申请模板 ID + 后端收集 openid）
- AI 单份批改触发（`POST /api/ai/grade`，需上传参考答案）
- 大文件方案升级：`cos-wx-sdk-v5` 直传 COS + 临时密钥
- tabBar 图标美化、深色模式适配

### P2 / 不做
- 管理员端、查重中心、模板/提示词管理、zip 打包、Excel 导出、文件清理

## 5. 关键技术方案

### 5.1 登录与鉴权
- 复用现有 `POST /api/auth/login`：`{ username, password, school_id }`（师生必须带 school_id；`GET /api/schools/all` 免登录可拉学校下拉）
- token 存 `uni.setStorageSync('token')`，用户信息存 `userInfo`
- App 启动校验 token（`GET /api/auth/profile` 失败即清态回登录页）；401 统一清态跳转
- P0 不做微信授权登录（避免 openid 绑定、隐私审核等复杂度，纯账号密码登录即可用）

### 5.2 文件上传（与 Web 分片上传的关系）
- Web 端分片上传（spark-md5 → chunk → merge）**保留不动**，小程序不走该链路
- 新增 `POST /api/upload/single`：multer 单文件（上限 100MB，扩展名黑名单与现有逻辑一致），落盘/COS 规则与 `mergeChunks` 完全相同，返回与 merge 一致的数据结构 `{original_name, file_path, file_size, mime_type, file_hash, ext}`
- 小程序端：选文件 → 逐个 `uni.uploadFile`（串行，进度条，失败单文件重试）→ 收集 descriptor 数组 → 调提交接口
- `file_hash` 置 null（小程序端不算全量 MD5），秒传/断点续传能力由 Web 端独享
- 手机端场景单文件一般 ≤100MB（拍照/拍视频/文档），够用；更大文件提示"请到网页端提交"

### 5.3 文件预览与域名白名单
- 统一走现有 `POST /api/files/urls`（Header 带 token）解析访问 URL，或 `GET /api/files/download?path=xxx&token=xxx`
- COS 公共读桶直出 URL → `uni.downloadFile` → `uni.openDocument`（pdf/doc/docx/xls/ppt）；图片用 `uni.previewImage`
- **微信后台需配置合法域名**（三类都要）：
  - request：API 域名（如 `https://你的域名`）
  - uploadFile：API 域名
  - downloadFile：API 域名 + COS 域名（如 `https://mengxiang-1405756754.cos.ap-beijing.myqcloud.com`）
- 域名必须 HTTPS 且已 ICP 备案；开发阶段勾选"不校验合法域名"

### 5.4 消息与角标
- P0：Tab 页 `onShow` 拉取 `GET /api/notifications/unread/count` → `uni.setTabBarBadge`；列表下拉刷新 + 分页 + 点按已读
- P1：微信订阅消息（截止提醒/批改完成），需模板 ID 与后端推送改造

### 5.5 TabBar 与角色分流
- 4 个原生 tab：首页 / 作业 / 消息 / 我的（tabBar 页面均在主包）
- **首页与作业列表页按 `userInfo.role` 分支渲染学生版/教师版**，避免 custom-tab-bar 的多角色页面集合超限问题
- 教师专属页（创建作业、批改、未交名单）从首页/作业详情二级进入

### 5.6 请求封装
- `utils/request.js`：Promise 化 `uni.request`；自动注入 `Authorization: Bearer <token>`；统一解包 `data`；`success === false` 时 toast `message` 并 reject；401 清态跳登录；网络异常统一提示
- `BASE_URL` 集中在 `utils/config.js`：开发 `http://本机局域网IP:3000`（真机调试需同一局域网），生产 `https://你的域名`

## 6. UI/UX 规范（延续 Web 视觉）

- 主色薄荷绿 `#52c4a0`，辅助天空蓝 `#5ab3f0`；页面背景 `#f6f8f7`，白色圆角卡片（16rpx）
- 状态色沿用 Element Plus 体系：成功 `#67c23a`、警告 `#e6a23c`、危险 `#f56c6c`
- 状态文案映射与 Web 对齐（作业：进行中/已关闭/已逾期；提交：已提交/已批改/已退回）
- 字号：标题 34rpx、正文 28rpx、辅助 24rpx，全部 rpx 单位
- 统一空态组件、下拉刷新、触底加载

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 小程序类目/资质审核（教育类目可能要求资质） | 按"工具 > 效率/信息查询"或与主体资质匹配的类目申请；账号密码登录不强制微信授权，降低隐私审核门槛；后台配置《用户隐私保护指引》（收集学号/姓名/文件） |
| 大文件上传不稳 | 单文件上限 100MB + 逐个串行上传 + 失败重试；超大文件引导 Web 端 |
| iOS `new Date('2026-08-30 23:59')` 解析失败 | 统一时间工具函数（`-` 转 `/` 后解析），倒计时/逾期判断集中处理；逾期最终以后端校验为准 |
| 包体积 | P0 全部主包（纯代码页面，远小于 2MB 限制）；后续按需分包 |
| COS 域名未加白名单导致预览失败 | 上线检查单明确列出三类合法域名清单 |

## 8. 里程碑

1. **M1（骨架）**：uni-app 工程初始化 + 请求层/状态/常量 + 后端 `/api/upload/single` + 登录页
2. **M2（学生链路）**：首页 → 作业列表/详情 → 提交（选文件/上传/备注）→ 提交记录 → 成绩查看
3. **M3（教师链路）**：工作台 → 课程/作业列表 → 创建作业 → 作业详情（提交/未交/催交）→ 批改（预览/打分/AI 结果）
4. **M4（收尾）**：消息中心 + 我的 + 改密码 + 班级；真机自测、按验收清单修复、提审材料准备
